## 1. 系统目标与技术连接

系统接收申请说明、金额、币种、票据归属、原始附件和政策文本，形成审计过程数据 `D=(X,E,P,F,B,T)`：

| 对象 | 含义 | 形成方式 |
|---|---|---|
| X | 申请或费用组 | 任务说明、金额和附件关系 |
| E | 多模态证据集合 | 原始文档、表格、图片和PDF |
| P | 政策条件 | 引用条款、信息角色、比较操作及处理后果 |
| F | 条件级事实校验 | 关系强度、引用、信息缺口和条件状态 |
| B | 金额边界 | 可报销、不可报销、待复核及最高合规金额 |
| T | 实际执行轨迹 | 输入引用、输出引用、操作、轮次和时间 |

三个核心模块连接在同一个多模态编码器之后。第一模块将政策运算结果注入语义关系判断；第二模块通过整项材料屏蔽和依赖重算形成贡献特征，预测支持与冲突引用；第三模块根据错误位置更新对应条件表示，并重新调用前两个模块。

配套程序承担输入校验、原件摘要核验、类型化比较、精确十进制金额运算和执行记录。材料读取、政策编译、神经模块和金额投影分别保留来源与计算接口，便于逐条件重放。

## 5. 运行契约与来源记录

`audit_engine/contracts.py` 使用严格Schema定义运行输入和监督输入。运行输入的主要字段为：

```text
workflow_id, input_version, application, evidence, conditions,
operands, amount_units, policy_coverage, unresolved,
policy_numbers, amount_programs, document_absences
```

### 5.1 证据与操作数

每项材料保存 `evidence_id`、`raw_ref`、`source_sha256`、文件类型、读取状态及原文片段。操作数保存：

```text
condition_id, role, evidence_id, value, value_type,
status, refs, depends_on, currency, dependency_groups
```

值类型支持文字、十进制数、金额、日期、日期时间、区间和集合。读取状态分为 `obtained`、`ambiguous`、`not_obtained`。日期、金额和币种分别核验；候选值存在分歧时保留对应来源。

`depends_on` 与 `dependency_groups` 描述材料依赖及等效来源。材料被屏蔽后，程序据此重新解析可用值；派生金额程序同时返回参与计算和一致性检查的全部来源。

### 5.2 引用与摘要

文字引用使用材料编号、片段编号和关键引文，视觉引用使用材料编号与原图观察说明。程序核验引文存在性、数值一致性、引用材料类型和路径范围。

case摘要覆盖申请、材料、条件、操作数及来源证明。监督标签与特征绑定该摘要，输入变化后重新建立对应关系。

<a id="s06"></a>
## 6. 材料读取和引用核验

材料读取由 `PatentReader` 与 `FrozenQwenEncoder` 组织。读取提示给出当前角色、值类型、角色定义及当前原始材料视图，生成带引用的事实。材料中的文字作为待审内容处理。

- DOCX按原始段落和表格行保存文字。
- XLSX保留表名、列名、行记录和原始值，集合读取可覆盖完整原表列。
- PDF按完整页面渲染，并保留页面序号。
- 图片使用原图或覆盖全图的自动视图，视觉观察保存可见字段说明。

读取器区分实际费用与政策限额、原始审批与申请人重述、发票出具日期与实际服务日期。有限类别角色返回声明的类别值，具体原文通过引文或视觉说明保存。

程序对类别、数字、日期、区间、集合和币种执行格式校验。格式失败或信息冲突时进行读取重试，结果和问题记录写入调用缓存。`reread_missing_patent_roles.py` 对缺失、冲突或类型不符的角色进行定向重读，已核验的来源事实保留引用链。

`read_original_text_field` 支持从原始DOCX读取命名字段、日期区间和完整人员编号集合；`bind_identifier_roles` 从原始表格绑定完整标识列。源文件摘要与原始段落或单元格内容共同校验，支持合同期限、授权名单、重复票据清单等场景。

<a id="s07"></a>
## 7. 政策条件与操作数

政策条件记录必要信息角色、角色来源、值类型、引用条款、比较操作、作用对象和处理后果。条款候选通过原文及适用范围核验后，获得明确的编译状态。

比较器实现相等、大小比较、区间包含、集合包含、明确授权、票据排重和闭合路线核验等操作。`EQ`、`LE`、`GE`、`WITHIN`、`IN_SET`、`AUTHORIZED`、`NOT_IN_SET`、`CLOSED_ROUTE` 的输入类型由具体操作约束。

确定性条件在操作数、币种、日期解释及政策来源完整时执行比较。对当前提供必要角色的材料，生成三维运算向量：

```text
成立：[1,0,0]
不成立：[0,1,0]
未决：[0,0,1]
```

另生成可执行标记 `m`。开放文本条件由明确声明的语义角色和来源覆盖进入关系判断，其政策比较标记保持0。

`ScalarCondition.rebuild(active, role_count)` 从可用材料中重建角色映射、必要角色、比较结果和可执行标记。这一接口在完整前向及每次材料屏蔽中共同使用。

<a id="s08"></a>
## 8. 共享编码与缓存

底座同一份权重提供两类调用：材料事实读取与隐藏状态编码。编码提示固定，取最后一个非填充输入标记的隐藏状态，得到4096维向量。

各材料独立编码其自身文本和图像视图，文本块和完整页面向量通过均值聚合。申请与政策条件分别编码，形成原始申请向量与条件向量。条件编码包含问题、角色定义、操作、条款、作用域及处理后果。

当前新增神经参数共13,541,385个：共享投影6,292,480个，关系模块3,550,211个，贡献引用模块1,030个，局部校正模块3,697,664个。

共享投影为：

```text
e_j = Linear_4096→512(raw_evidence_j)
h_k = Linear_8192→512([raw_application; raw_policy_k])
```

`CaseFeatures` 保存case摘要、材料顺序、条件顺序、原始向量及编码签名。签名包含固定底座revision、读取LoRA摘要、处理器图像预算、文本分块与聚合方式。

材料视图缓存与完整case缓存分别保存。改变读取LoRA、编码提示或材料内容时，重新生成对应特征。预测入口将特征签名与联合checkpoint签名逐项核对，保证读取适配和神经模块使用一致的编码基础。

## 9. 第一模块：政策引导关系判断

实现：`audit_engine/models/heads.py::RelationModule`。

### 9.1 角色上下文

对每个必要角色，在当前可用材料中取提供者向量均值，并附加角色是否可用的标记。8个角色槽拼接后为 `8×(512+1)=4104` 维，经线性投影得到512维上下文 `b_k`。

具体来源编号和值分别保留；角色均值用于神经网络语义计算，类型化操作数用于政策比较。

### 9.2 双通路与门控

对条件k、材料j：

```text
semantic_input = [h_k; e_j; b_k]                    # 1536维
policy_input   = [o_kj; m_kj]                     # 4维
semantic       = Linear_256→512(SiLU(Linear_1536→256(semantic_input)))
policy         = Linear_256→512(SiLU(Linear_4→256(policy_input)))
gate           = sigmoid(Linear_1540→512([semantic_input; policy_input]))
u_kj           = semantic + gate ⊙ policy
p_kj           = softmax(Linear_512→3(u_kj))
```

三类关系概率依次为支持、冲突、无法判断。政策通路直接接收运算结果，语义通路结合当前材料与跨材料角色上下文，门控参数在条件级监督下更新。

### 9.3 条件强度

令 `J_r` 为角色r的当前材料提供者集合：

```text
S_k = min_r max_{j∈J_r} p_kj(support)
C_k = max_j p_kj(conflict)
```

空角色集合的支持强度按0处理。该汇总将支持建立在必要角色覆盖之上，同时保留任一材料提供的冲突信号。

## 10. 第二模块：证据贡献核验

实现：`training/forward.py::forward_condition` 与 `models/heads.py::ContributionModule`。

对每份材料j，复制当前可用掩码并将该项设为不可用，然后重建操作数、派生金额、角色映射、上下文和比较结果，再计算关系强度：

```text
delta_kj^support  = S_k(E) − S_k(E\{e_j})
delta_kj^conflict = C_k(E) − C_k(E\{e_j})
```

同一份材料的全部原图、页面、文字和派生操作数通过材料标识及依赖链统一失效。合同、考勤和签收一致性检查等约束来源也进入依赖记录。

支持与冲突引用分别使用线性头：

```text
q_support  = sigmoid(Linear_514→1([u_kj; p_support; delta_support]))
q_conflict = sigmoid(Linear_514→1([u_kj; p_conflict; delta_conflict]))
```

引用训练使用已核验的引用标签，贡献值作为可学习特征参与预测。等效材料存在时，角色覆盖与引用极性共同识别可替代依据。引用概率经过0.25阈值和来源核验后形成支持、冲突两组记录。

该模块连接完整材料依赖与具体引用，便于回查结论依据、检查遗漏材料及定位依赖异常。

<a id="s11"></a>
## 11. 事实状态与错误定址

### 11.1 事实状态

每个条件保存 `object_id`、`condition_id`、支持强度S、冲突强度C、信息缺口G、引用、缺口明细、状态及错误向量。

G包括必要角色缺失和确定性条件的操作数、币种或日期解释未决。状态按下列规则生成：

| 条件 | 状态 |
|---|---|
| G=1 | insufficient，证据不足 |
| G=0，S≥0.40且C≥0.65 | contradictory，事实矛盾 |
| G=0，仅S达到阈值 | satisfied，满足 |
| G=0，仅C达到阈值 | failed，不满足 |
| 其余 | insufficient，证据不足 |

缺口明细区分 `not_read`、`ambiguous` 和 `confirmed_missing`，分别对应读取未决、事实歧义和经过完整来源核验的缺件。

### 11.2 三个错误分量

`v=[v_ref,v_rule,v_dep]` 直接从运行输出构造：

- `v_ref`：必要信息已取得，但对应极性的引用未覆盖信息提供者。
- `v_rule`：可执行政策比较与当前模型关系类别不一致。
- `v_dep`：已引用材料存在显著负贡献，或重要材料的正贡献超过遗漏阈值且缺少等效依据。

错误上下文记录被定位的材料表示、比较结果、角色和可用标记。错误检测器使用当前事实、概率、来源和政策运算结果，训练目标单独进入监督损失。

<a id="s12"></a>
## 12. 第三模块：局部循环校正

实现：`models/heads.py::LocalCorrector`。

### 12.1 校正资格

信息完整、政策已核验、操作数无歧义且检测到关系或引用错误的条件进入 `eligible`。事实缺件、读取未决及政策范围未决进入对应的材料核验或复核流程。

### 12.2 上下文与更新

每个错误角色槽由512维材料均值、3维比较结果和1维可用标记组成。8个槽与3维错误向量拼接，得到4131维输入；错误投影输出512维。

当前事实编码为 `[S,C,G,state_one_hot]`，共7维。与角色上下文和错误表示拼接后为1031维，经投影得到512维校正上下文c。

```text
z       = [v; h; c]                         # 1027维
g       = sigmoid(Linear_1027→512(z))
a       = tanh(Linear_1027→512(z))
h_next  = LayerNorm(h + g ⊙ a)
```

LayerNorm使用可训练缩放和偏置，`eps=1e-5`。实现按 `eligible` 索引选中条件行并执行更新，其余条件直接复用原张量。

### 12.3 局部循环

更新后的条件表示重新进入关系判断、完整材料屏蔽、引用预测和错误检测。最多执行2轮；错误归零或达到稳定状态时停止。原始材料、政策及操作数在循环中保持固定，新的申请重新形成初始条件表示。

该接口使修改范围与错误位置一致，并保留各轮实际执行事件。

## 13. 实际训练阶段与损失

### 13.1 分阶段优化

| 阶段 | 训练数据 | 可训练模块 | 实际优化步数 |
|---|---|---|---:|
| B1 | 原始训练工作流 | 共享投影、关系模块 | 72 |
| B2 | 原始训练工作流 | 贡献引用模块 | 96 |
| B3 | 原始训练工作流 | 共享投影、关系、贡献 | 72 |
| B4 | 原始工作流及附件删除变体 | 共享投影、关系、贡献 | 132 |
| C | 可校正条件与受限扰动筛选 | 局部校正模块 | 70 |

C阶段固定前两个模块参数，同时保留它们对临时条件表示的连续计算梯度，使监督可传回局部校正模块。代码同时支持C2联合调整接口；交付权重对应上述五个阶段。

实际非零梯度记录：共享投影276步、关系模块276步、贡献核验模块300步、局部校正模块70步。

### 13.2 损失

- B1：带类别权重的掩码关系交叉熵。
- B2：掩码引用二元交叉熵。
- B3、B4：关系损失与引用损失之和。
- C：关系损失＋引用损失＋`0.5×状态损失`，作用于可校正条件的有效监督位置。

状态辅助分布按 `S(1−C)`、`(1−S)C`、`(1−S)(1−C)`、`SC` 对应满足、不满足、证据不足及事实矛盾，目标状态使用带下限的负对数损失。

损失先对每条件的有效位置平均，再对工作流平均。阶段日志记录训练损失、条件状态与关系指标、引用指标、校正后的修正和误改数量、优化步数及选点结果。

## 14. 材料读取LoRA

### 14.1 参数和训练

LoRA加载到语言解码器最后12层的 `q_proj/k_proj/v_proj/o_proj`，共48个目标模块、96个适配张量、5,111,808个适配参数。秩为16、alpha为32、dropout为0.05。

本次读取适配使用116条已审核材料问答，学习率 `1e-5`，单条批量，梯度累积8次，训练1轮、15个优化步。AdamW权重衰减为0.01，使用预热及余弦学习率调度。

材料问答验证损失由0.631降至0.604。适配结束后，重新编码67个输入，三个模块在该读取LoRA对应的真实特征上完成分阶段训练。

### 14.2 数据格式和连接

问答记录绑定工作流、来源组、材料摘要、原始文件、读取提示及事实回答，并记录审核人、划分和原始来源。训练脚本核验划分与来源摘要，保存适配器、优化状态及训练日志。

读取LoRA负责金额、日期、类别、人员及原始记录等事实提取；神经模块据此执行关系、引用和局部校正。适配器摘要进入特征签名，保证配套使用。

<a id="s15"></a>
## 15. 附件变体与内部扰动

事实变化修改训练副本的实际材料集合。本次保留20个经原件核验的附件删除变体：删除材料后刷新证据集合、读取值、操作数依赖、条件状态和监督摘要，保留母工作流来源组。

内部扰动作用于信息充分的条件表示，材料、政策和原正确监督保持固定。程序沿监督损失增大的方向构造候选扰动，并限制相对幅度：

```text
h_adv = h + rho × ||h||₂ × grad_h(L) / max(||grad_h(L)||₂, epsilon)
```

候选需同时通过原判断正确、扰动后产生错误、运行检测器可定位三个筛选环节。本次C阶段每轮筛选159个候选，接受数为0；阶段优化使用运行检测器定位的自然关系与引用错误。训练记录分别保存候选数、原正确条件数、制造错误数和实际接受数。引用核验掩码在训练筛选与正式推理中共同使用。

自然错误与扰动错误均通过同一运行检测及 `eligible` 接口进入局部校正，监督用于优化与评估恢复效果。

<a id="s16"></a>
## 16. 来源绑定的金额程序

金额表达式由 `BoundMoneyExpression` 执行，使用精确Decimal数值和白名单表达式。操作数来自带引用的实际材料，限额来自已核验政策数值，表格聚合绑定原始表名、列名、日期范围、人员集合及签收约束。

支持值、乘积、和、最小值及汇率换算等组合；约束参与的材料与数值计算材料共同进入来源记录。每次材料屏蔽重新执行表达式，角色映射与比较结果使用该次有效来源。

### 16.1 合同餐补的实际连接

合同餐补已连接以下来源：

1. 原始合同中的期间和授权人员名单；
2. 原始每日考勤表中的日期、人员和出勤数；
3. 原始签收表中的各人员工作天数及签名；
4. 原始政策中的日标准和项目上限；
5. 模型从发票原图读取的总额、发票类别及服务起止日期。

程序按人员逐一比较考勤天数和签收总数，以合同期间与人员集合限定有效记录。餐补金额程序按 `min(日标准×有效工日数, 合同上限)` 计算。缺签名、人员不符、天数不一致时生成对应核验问题。

### 16.2 金额投影

金额单元具有明确的申请额、币种、适用上限和材料支持金额，共享额度先合并到费用组。投影按接受、拒绝、复核状态生成：

```text
A_claim = A_ok + A_no + A_review
```

超过已确定上限的部分进入不可报销金额。未知上限或关系未决的金额进入复核，明确拒绝的单元记为拒绝。最高合规金额 `A_max` 单独记录材料及政策支持的上限；申请范围内的三类金额用于当前申请分配。

<a id="s17"></a>
## 17. 完整附件缺件核验

`DocumentAbsenceProof` 将已确认缺件绑定到具体条件及信息角色。每份原始附件保存摘要、已检查文本片段、完整图像或PDF页面、逐视图观察说明及原始调用摘要。

`read_submission_document_absence.py` 对全部附件逐视图读取，针对每项文件要求返回 `present`、`absent` 或 `uncertain`。只有全部来源视图明确为缺失时，才生成该角色的完整缺件证明。

Schema校验保证来源集合覆盖所有附件，文本覆盖全部片段，图像使用完整原图，PDF覆盖全部页面。新增附件、源摘要变化、遗漏页面或相反事实读取会使证明失效，系统据新材料重新核验。

本次运输场景检查6份原始附件、36个完整来源视图，形成实际运单与签收证明的缺件记录。系统依据原政策中“任一证明缺失则不予报销”的条款执行相应后果，并在事实表与执行轨迹中保存来源证明。

## 18. 推理流程与输出

运行流程：


## 23. 开发扩展与检查接口

新增政策场景时，按“条款及适用范围核验→角色定义→类型化读取→比较操作或开放语义条件→处理后果→金额程序”组织配置。金额单元按可靠的分项对应关系建立，共享额度按费用组汇总。

新增输入后先运行Schema及来源检查，确认操作数与引用绑定，再重建相关底座特征。对已核验训练工作流生成变体时，同步更新附件、读取、依赖、标签和case摘要。

开发检查重点包括：

1. 角色和值类型与原始材料相符，引用可以定位到原件；
2. 屏蔽材料后，相关操作数、约束来源和比较结果同步重算；
3. 有效监督掩码、类权重与工作流平均方式一致；
4. 校正仅更新选中的条件行，冻结模块保留对临时表示的梯度；
5. 缺件证明覆盖全部材料，新增附件或相反读取触发重新核验；
6. 金额投影保留明确的申请额、限额、支持上限和处理状态；
7. 配套读取LoRA、特征与联合checkpoint签名一致。
